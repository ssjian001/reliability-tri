# V1.1-ER-r3 复审（r2 评审整改核验）

- 评审方式：运行 `tools/validate_assets.py`；对 r2 评审的 P0/P1 逐条复核；对模板做归一语义手算
- 结论：**P0-1（契约自相矛盾）已清除；P0-2（温度语义）只改了定义、没改样例，仍然阻断**。另有 1 项 P1、4 项 P2 残留。

- 01 的可复现口径改为“同构建逐字节、跨版本按容差”（`01:53`），`AnalysisRun` 补版本字段（`01:125`）。

## 2. 仍阻断（P0）：表达式里的数字常量没有单位语义

02:45 规定“absolute 归一到 K，表达式只读取已归一值”，但模板中的字面量仍是裸数，且按 °C 书写：

| 模板用例 | 期望 | 按 02:45 归一后实际 |
|---|---|---|
| 模板 1 / 55 ℃ 正常 | PASS | `328.15 <= 70` 为假 → SKIPPED |
| 模板 1 / 55 ℃ 超阈值 | FAIL | 同上 → SKIPPED |
| 模板 2 / 25 ℃（3 条） | PASS / PASS / FAIL | 因子 `-1.185`，前两条 FAIL；第三条碰巧仍 FAIL |

即 **6 条用例中 5 条结果相反**。位置：

- `attachments/rule_templates.yaml:21`：`local_ambient_temp <= 70`
- `attachments/rule_templates.yaml:87`：`temp_derating_factor: "1 - ((case_temp - 25) / 125)"`
- 同一模板 `:84-86` 新增了 `temp_derating_delta_ref_c/max_c`，但公式没有使用
- `:125` 注释称“85/150 三组用例进 CI”，实际三条用例 `case_temp` 均为 25（`:112/:117/:122`）

复算：

```text
1 - ((298.15 - 25) / 125) = -1.1852
1 - ((328.15 - 25) / 125) = -1.4252
```

**修复建议（二选一，并写进 DSL 规范）：**

1. 字面量强制带单位：`local_ambient_temp <= 70 degC`、`1 - ((case_temp - 25 degC) / 125 K)`，编译期换成 SI；或
2. 规定字面量即 SI 无量纲值，模板改为 `case_temp - 298.15`、`125` 保持 K 差值。

无论哪种，都要补 25/85/150 ℃ 三条折减因子用例，并让 `temp_derating_delta_*` 参与计算或删除。

## 3. P1 残留

1. **`published` 前 ≥3 用例的门禁没有实现**：`rule.schema.json:343-344` 仍是 `minItems: 1`，只把“≥3 且覆盖 normal/boundary/invalid”写在 description；`tools/validate_assets.py` 也不检查状态与 kind。CI 全绿不代表发布门禁成立。建议加 `if status=published then tests minItems=3` + `contains` 约束。
2. **状态词表仍漂移**：`01:177` 的 promote 流转仍写 `approved`，schema 与 02 已统一为 `published`。
3. **规则编写工作量不现实**：`01:228` 给 ≥60 条规则的编写/单测/双审估 10-15 人日，折合每条约 1.5-2.5 小时（含证据核对、3 条用例、双人评审），明显偏低；建议按规则族给出 0.5-1 人日/条的区间并说明依据。
4. **README 未随 r3 同步**：`V1.1/README.md:2` 仍是“版本 V1.1”，`:15` 仍写“相对误差容差 ≤0.1%”，与 `03:74` 的 `max(abs_floor, rel×ref)`、寿命类 1% 不一致。

## 4. P2 残留

1. **`error_code` 的 `null` 分支不可达**：`rule.schema.json:393-403` 的 `type` 是 string，enum 却含 `null`；要么把 type 改为 `["string","null"]`，要么删掉 null。
2. **模板 3 的量类型标错**：`rule_templates.yaml:138` 给 `thermal_resistance_ca` 标 `quantity_kind: absolute`，但字典中 `degC_per_W` 属 `temperature_gradient`（delta 类）。若按 absolute 施加 273.15 偏移，热阻会被算错。
3. **“domain 与基准集一致”不成立**：`rule.schema.json` 的 domain 只有 8 个规则域，benchmark 有 13 个（多 5 个对抗/边界域），schema description 却写“与基准集 domain 字段一致”。建议改为“8 技术域 + 5 对抗域”的显式说明。
4. **ReliaTrack 幂等键仍有碰撞风险**：`attachments/reliatrack-interface-spec.md:22` 仍是“导出时间戳 + 行数”。同一秒内同规模的两批会撞键，建议 UUIDv7 或内容哈希。
5. **`C` 别名仍歧义**：`unit_dictionary.yaml` 把 `C` 作为摄氏别名，但 `charge` 的 canonical 也是 `C`（且无 `C` 单位项）。当前只有“C=摄氏”一种解析，库仑量无法表达；建议去掉单字母 `C` 别名或要求显式维度。

## 5. r4 最小验收清单

1. 模板 1/2 在 25/85/150 ℃ 下的判定与手算一致，5 条错误用例转为通过。
2. DSL 规范写明字面量单位语法，schema/parser 有对应校验。
3. `status=published` 时 `tests≥3` 且 kind 覆盖三类，validator 拒绝不合规规则。
4. `01:177` 改 `published`；README 与 03 容差口径同步。
5. `thermal_resistance_ca` 改为 delta；`error_code` 的 null 分支处理掉。
