# AI电子硬件可靠性分析系统｜系统工程规格书
版本 V1.1 · Engineering Implementation Ready｜2026-11-22

> 修订性质：本版为实施就绪版（Implementation Ready）。技术决策（规则引擎架构、容量基线、集成方式）已定，可直接用于研发任务拆解。变更逐项对应《CHANGELOG.md》。

## 1. 目标与边界
建设面向通用智能硬件的可靠性工程辅助平台，覆盖元器件、PCB/PCBA、模块/传感器、电源及整机。支持设计输入审查、器件应力/降额、DFMEA辅助、FA假设分析、DVP&R策划、仿真结果审查和报告追溯。

系统是工程决策辅助工具，不替代专业工程师签核、认证机构、制造商数据手册或专业仿真软件。AI不得把推测写成已证实根因，不得在输入不足时编造参数。

## 2. 用户角色与权限
- 系统管理员：用户、权限、模型、规则发布与审计配置。
- 可靠性负责人：规则审批、高风险复核、风险签核。
- 硬件工程师：设计数据导入、分析任务、问题处理。
- DQE/质量工程师：DFMEA、验证策划、FA闭环。
- 仿真工程师：仿真任务、参数及结果导入。
- 只读审阅者：查看授权项目与报告。
采用RBAC及项目隔离；规则发布、模型升级、高风险关闭执行双人复核。

## 3. 总体架构
1. 交互层：项目工作台、Datasheet 分屏校对台、设计审查、DFMEA、FA、验证计划、报告中心。
2. 业务编排层：任务流、审批、通知、版本管理。
3. 分析服务层：规则引擎、确定性计算、RAG检索、LLM推理、结果校验。
4. 数据知识层：项目/BOM、器件库、规则库、失效模式库、标准库、案例库、证据库。
5. 工具连接层：EDA、PLM、MES、实验室、热仿真、PCB可靠性、SPICE及降额工具。
6. 治理安全层：身份认证、权限、审计、脱敏、模型评估、监控、备份。

核心原则：规则优先、模型辅助；确定性计算不交给LLM自由发挥；结论区分事实/规则推导/工程假设/待验证建议；每次分析保存输入快照、模型版本、规则版本、知识版本和执行日志。

### 3.1 规则引擎技术架构（V1.1 定案；三类规则执行器）
```
Rule Definition（规则表达式 + 输入参数 + 单位定义）
   ↓
Parser / AST（语法白名单、类型检查、禁止任意代码执行）
   ↓
Unit Normalization（单位别名识别、SI归一、维度检查）
   ↓
Deterministic Evaluator（确定性求值、边界校验）
   ↓
Finding + Evidence（判断、依据、规则版本、计算过程）
```
规则按复杂度分三类执行器（rule_type，机读定义见 rule.schema.json，模板见 02 §2.2）：
1. **declarative_expr**：静态布尔/四则规则，走上述 DSL 流水线；expression 禁止函数调用。可用 asteval/simpleeval 类安全沙箱执行。
2. **lookup_curve**：二维曲线插值/包络规则（高温功率折减、MLCC 偏压曲线、MOSFET SOA），走**曲线插值引擎**：curve_eval 配置插值方法（如 log_log_linear）、温度折减因子与安全裕度系数，边界越界显式报错；曲线表来源为器件 datasheet 曲线（Artifact 结构化产物）。
3. **script_plugin**：多步物理计算（Arrhenius 寿命、多热阻链结温、IPC-2152 载流），走**受控计算插件**：插件注册表管理（module 版本化 + 代码审计 + 白名单包 + 只读输入），执行结果与阈值比较由 expression 承载；数值精度受 03 §5 浮点容差约束。
- 通用禁令（全类型）：禁止 `eval()`、禁止 LLM 执行规则、禁止动态导入与文件访问、禁止网络访问。
- 首版 declarative_expr DSL 边界：比较 `> >= < <= == !=`、逻辑 `AND OR NOT`、算术 `+ - * /`、受限 `IF`。
- 单位系统采用 Pint 类成熟实现，附加电子工程单位别名与倍率映射表（见附件 `unit_dictionary.yaml`）；不同物理维度直接比较直接报错。
- 缺失值、除零、单位不兼容均返回明确错误码，不自动猜测。
- 求值确定性要求见 §3.2；插件数值精度口径见 03 §5。

### 3.2 分析结果的确定性与可复现性（V1.1 新增）
- 确定性结果可复现口径（r3 细化）：**同一构建内**（engine/unit_dict/rule 版本全同）结果逐字节一致；**跨版本重算**按数值容差比对（03 §5.1：max(abs_floor, rel×ref)）并标注版本差异。AnalysisRun 记录 engine_version/unit_dict_version/prompt_version/rule_version/knowledge_snapshot（unit_dict_version 建议内容哈希）。
- LLM 生成内容（解释、候选风险措辞）允许存在差异，但不得改变确定性计算结果；LLM 输出中的数值若与确定性结果冲突，以确定性结果为准并标记冲突。
- 复现边界：每次 AnalysisRun 记录 engine_version、unit_dict_version、rule_version、knowledge_snapshot、model_version、prompt_version；任一变更后的历史重算须显式标注。

## 4. 功能需求
- FR01 项目与产品建模：项目、产品、板卡、模块、器件、版本、工况和使用剖面。
- FR02 数据导入：CSV/XLSX/JSON及API；检查字段、单位、范围、重复项、版本冲突和来源。
- FR03 设计输入审查：电气、热、环境、寿命、机械边界与接口约束的完整性/一致性检查。
- FR04 器件降额：电压、电流、功耗、温度、纹波、频率、SOA、寿命等；展示公式、输入、额定依据和裕量。
- FR05 PCB/PCBA风险：热、铜箔/过孔、板弯、焊点、CAF、腐蚀、振动、污染及制造变异。
- FR06 DFMEA辅助：功能链、失效模式/原因/影响、控制措施、S/O/D或AP建议；评分由工程师确认（默认评分表见附件 `dfmea_scoring_template.md`，企业批准后替换）。
- FR07 FA辅助：现象、条件、样品、波形/日志/图片归档；输出候选机理、支持/反证、区分实验和证据缺口。（V1.1 边界：附件归档与人工标注文本输入；自动图像/波形多模态解析规划于 V2.0/P2。）
- FR08 DVP&R生成：目的、条件、样品量、顺序、判据、前后测、FA要求；非标准来源数值标记为建议值/TBD。
- FR09 工具链接：仿真/计算任务通过适配器调用或导入，校验单位、版本、边界条件。
- FR10 风险闭环：责任人、期限、措施、验证证据、审批与审计。
- FR11 报告：可追溯导出Markdown/Excel/PDF等受控模板。
- FR12 规则覆盖率管理（V1.1 新增）：持续报告规则覆盖盲区，见 §4A。

## 4A. 规则覆盖率管理（V1.1 新增）
系统不仅报告「发现了多少风险」，还须报告「哪些风险没有规则覆盖」：
- 规则覆盖器件类别比例（已发布规则触及的器件类别 / 知识分类定义的类别）。
- 规则覆盖失效机理比例（已发布规则引用的机理 / 失效模式库定义的机理）。
- 未覆盖高风险场景数量：BOM 中高危器件类别（电源路径、功率、高压/射频、电解、连接器、电池）在当前规则库无适用规则的数量清单。
- 规则适用性不确定的分析比例：因 applicability 无法判定而跳过的分析占比。
上述四项进入报告中心与发布评审；新器件类别导入时自动输出覆盖缺口提示。

## 5. 核心数据模型（V1.1 修订版）

### 5.0 基础值对象 MeasuredParam（V1.1 新增）
为落实「所有参数需包含单位、来源、版本、生效日期、适用范围及可信等级」与验收用例 T03（单位混用归一并保留原值），所有物理量字段统一采用 MeasuredParam 结构存储，不使用裸浮点数：
```
MeasuredParam {
  raw_value: "3300",             // 原始输入值（保留原始精度/字符串）
  raw_unit: "mV",                // 原始单位
  norm_value: 3.3,               // 归一化标准单位值（SI）
  norm_unit: "V",                // 标准单位
  quantity_kind: "absolute | delta",   // r3 新增：绝对量/差量（温度双轨，复审 P0-2）
  source_type: "datasheet | bom | simulation | manual | assumed",
  evidence_id: "EVD-2026-001",   // 关联证据ID（假设则为空）
  source_level: "A | B | C | D",             // 来源权威性（三轴之一）
  extraction_status: "human_verified | ai_unverified | measured",  // 抽取确认状态（三轴之二）
  applicability_status: "in_scope | out_of_scope | unknown",       // 适用性（三轴之三）
  revision: "Rev.C",
  effective_date: "2026-01-15",
  applicability_note: "Ta = -40~85℃"
}
```
防呆约束（r2+r3）：未经人工确认（Datasheet 管线 §7A Step4）的 AI 抽取参数，extraction_status 自动标记为 **ai_unverified**；正式判定（PASS）要求 source_level ≥B 且 extraction_status=human_verified/measured 且 applicability_status=in_scope **三轴同时达标**，任一不达标仅可用于预演或转人工（复审 P1-1：C 级不得静默 PASS）。

## 5A. 容量规划与性能边界（V1.1 定案）
| 指标 | V1 基线 |
|---|---|
| 单项目 BOM | 500 行 |
| 工况组合 | 3 组 |
| 单次分析规模 | 1500 个器件-工况组合 |
| 同时运行分析任务 | 5 个 |
| 单次输入文件 | 50 MB |
| 单项目附件存储 | 2 GB |
| 常规规则分析 P95 | ≤30 秒 |
| 性能统计口径 | 单个分析 Run，不是单个器件 |
- P95≤30秒 的口径：单个分析 Run 的**规则分析任务**（规则求值+单位归一+检索+Finding 生成），**不包含**外部仿真求解、长时间文件解析（大 PDF/Office）及人工审批——这些走异步。
- BOM 硬上限 2000 行（超出按板卡/模块拆分导入）；超基线负载属容量扩展需求，不进 V1 承诺。
- 检索库规模假设：器件库 ≤50 万料号、失效模式库 ≤1 万条、规则 ≤5 千条——超出需重新评估检索架构。

## 6. API建议（V1.1 修订版：完整资源分组）
REST/JSON + OpenAPI；幂等键、权限校验、分页、统一错误码、追踪ID及审计贯穿全部接口。复杂分析统一返回 202 Accepted + run_id。

### 6.1 项目、BOM 与应力数据接入
- POST /v1/projects：创建项目与产品版本。
- POST /v1/projects/{id}/artifacts：上传原理图网表（Netlist）、Datasheet PDF、FA 波形/图片；返回 artifact_id 与文件校验和 checksum。
- POST /v1/projects/{id}/bom:import：导入 BOM 表（结构化 JSON/XLSX；自动触发单位归一化与字段门禁检查，返回校验报告）。
- POST /v1/projects/{id}/stresses:batch-upsert：批量导入或更新器件工作应力（ComponentStress），关联工况剖面（OperatingProfile）。

### 6.2 异步分析任务编排（统一返回 202 Accepted + run_id）
- POST /v1/analyses/design-review：触发设计输入与接口一致性审查。
- POST /v1/analyses/derating：触发器件降额与确定性规则引擎计算。
- POST /v1/analyses/dfmea：触发 DFMEA 失效链辅助生成。
- POST /v1/analyses/fa：触发 FA 故障树与候选机理假设推演。
- POST /v1/verification-plans：基于已确认风险生成 DVP&R 验证测试计划。
- GET /v1/analyses/{run_id}：查询任务状态（PENDING / RUNNING / COMPLETED / FAILED）、输入快照版本及执行日志。
- GET /v1/analyses/{run_id}/findings：分页获取分析结果列表（支持按 risk_level、conclusion_tag 过滤）。

### 6.3 风险闭环、审批与受控报告
- POST /v1/findings/{id}/disposition：工程师对单条结论处置（确认风险、补充数据缺口、驳回误报并填写理由）。
- POST /v1/approvals：双人复核与高风险签核（对象涵盖高风险 Finding、Rule 发布、模型升级）。
- POST /v1/reports:export：生成带全链路追溯水印（输入快照/规则版本/模型版本）的受控报告（Markdown / XLSX / PDF）。

### 6.4 规则与知识库生命周期管理
- POST /v1/rules、PUT /v1/rules/{rule_id}：创建或修订规则（初始状态强制为 draft）。
- POST /v1/rules/{rule_id}:test：运行规则自带单元测试集（tests）并返回覆盖率与精度结果。
- POST /v1/rules/{rule_id}:promote：流转规则状态（draft → in_review → shadow → published → deprecated）。
- POST /v1/rules/{rule_id}:rollback：回滚至历史受控版本。

## 7. AI与规则协同流程
输入校验/单位归一 → 确定性规则计算 → 检索适用证据 → LLM解释和生成候选风险 → 后置校验（引用、数值、适用边界）→ 人工确认。无证据时明确输出资料不足。关键风险不得自动关闭。

### 7.1 规则执行状态机与优先级（V1.1 新增）
单条规则对一个器件-工况的执行状态按**最先命中**取值（复审 P0-3）：
| 优先级 | 状态 | 触发 |
|---|---|---|
| 1 | DATA_GAP | 必填输入缺失 |
| 2 | NOT_APPLICABLE | applicability 不匹配 |
| 3 | SKIPPED_PRECONDITION | preconditions DSL 不满足 |
| 4 | CONFLICT_UNRESOLVED | 证据冲突无法按 02 §3.1 裁决 |
| 5 | PASS / FAIL | 求值完成 |
非 PASS/FAIL 状态写入 Finding.execution_status 并附原因；每个状态至少一个负例单测（进 CI）。

## 7A. Datasheet 参数抽取与人机协同管线（V1.1 新增）
为避免规则引擎在试点期因「缺少器件额定参数」而大面积报缺口，定义独立的离线知识入库流水线：
```
[PDF Datasheet 上传]
   ↓ 1. 版面解析与表格/曲线提取（区分文本参数表 vs 降额/偏压曲线图）
   ↓ 2. LLM 结构化抽取（强制输出带页码、原文摘录、原始单位的候选 JSON）
   ↓ 3. 确定性格式校验（单位可解析性、物理常识范围、必填项完整性）
   ↓ 4. 器件工程师对照原文高亮校对（UI 左右分屏：左 PDF 原页高亮，右结构化表单）
   ↓ 5. 签核入库（状态标记为 Evidence Level A，锁定 checksum 供规则引擎调用）
```
核心防呆设计：未经人工点击确认（Step 4）的 AI 抽取参数，confidence_level 自动标记为 **D**；确定性规则引擎执行正式降额判定时**禁止直接使用 D 级参数放行**，仅可用于预演提示。曲线图提取产物（SOA/偏压/折减曲线）落为 lookup_curve 类规则可引用的结构化表（见 02 §2.2 模板 2）。

## 8. 非功能需求
可用性试点目标≥99.5%；常规规则分析P95目标≤30秒（口径见 §5A），复杂任务异步执行；规则、器件类别、工具适配器可扩展；监控任务成功率、延迟、引用错误、人工改写率；配置/规则可回滚；CI包含规则单测、接口契约和模型回归。

## 9. 安全治理
SSO/OIDC、RBAC、项目隔离、TLS及静态加密、密钥托管；上传文件恶意内容检测；防提示注入；外部知识源白名单；数据分类分级、脱敏、保留/删除策略；审计登录、导入、查询、规则/模型变更、审批及导出。敏感设计资料优先私有化或受控专有云。

### 9A. 标准文本版权与部署治理（V1.1 定案）
标准库仅存元数据（标准号、版本、条款号、标题）与指向受控副本的引用指针；IEC/ISO/JEDEC/JIS 等受版权保护的标准全文不入库、不展示原文，展示以条款号+适用要点转述并标注出处。企业内部规范按企业文档密级管理。部署侧治理：受控副本的存储位置、访问审计与备份策略随部署环境（私有化/受控专有云）在立项时确定。

## 10. 部署与技术路线
初期建议模块化单体 + 独立推理/计算服务，避免过早微服务化；容器化部署，开发/测试/生产隔离。增长后拆分规则、检索、任务编排服务。

| 阶段 | 周期 | 交付/退出条件 |
|---|---:|---|
| 需求与数据盘点 | 1-2周 | 场景、数据字典、权限矩阵、试点项目 |

基准集生产工作量单列（r3 修正：benchmark.domain 实有 13 类——8 技术域 + 5 对抗/边界域）：技术域 8 × 30-50 条 + 对抗域 5 × 10-20 条 × 双人标注，预估 18-25 人日；首批规则 ≥60 条的编写/单测/双审按 0.5-1 人日/条区间估 30-60 人日（含证据核对、3 条用例、双人评审）。合计须在验证集成阶段前两周启动招募与培训。

## 11A. ReliaTrack 集成（V1.1 定案为批量交换）
ReliaTrack 为 PySide6 桌面应用（apsw/SQLite，schema v29），**无 REST API**（2026-11-22 代码实查：无任何 Web 框架），故 V1.1 采用 **CSV/Excel 批量交换适配器**，实时 API 集成留待 ReliaTrack 侧演进后升级。数据链与字段映射见附件 `reliatrack-interface-spec.md`。

数据闭环（设计风险识别 → 验证 → 失效分析 → 知识沉淀）：
1. 本系统：识别风险、生成验证计划（DVP&R）。
2. ReliaTrack：承接为测试任务、样品、条件、执行，产出结果与失效记录。
3. 批量交换回本系统：结果与失效记录进入证据库（B 级）与 FA 输入。
4. 知识库与规则库更新：经专家审核后发布，**不自动修改正式规则**。

## 12. 主要风险
数据质量差：导入门禁、采集模板标准化与责任人；规则误用：明确适用边界和版本；AI幻觉：引用强制、证据分级及后验校验；工具接口变化：适配器隔离；采纳率低：嵌入既有评审并支持网表/模板批量导入；责任不清：明确最终签核责任。
