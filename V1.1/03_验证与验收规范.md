# AI电子硬件可靠性分析系统｜验证与验收规范
版本 V1.1 · Engineering Implementation Ready｜2026-11-22

> 修订性质：实施就绪版。基准集 JSON Schema、标注与仲裁流程、评分一致性、分级回归、注入语料均为定案；机读附件：`benchmark.schema.json`、`prompt_injection_dataset.json`。变更对应《CHANGELOG.md》。

## 1. 验收目标
验证系统的数据导入、规则计算、证据检索、风险解释、验证建议、审计和人工审批能力。验收关注正确性、可追溯性、边界意识和工程可用性，而非文字流畅度。

## 2. 验证原则
规则计算与AI生成分开验证；冻结基准数据集；数值结果与独立计算比对；高风险漏报权重大于低风险误报；开发集与盲测集隔离；模型/提示词/知识/规则变更均触发分级回归（见 §11）。
新增（V1.1）：确定性规则结果的可复现性纳入验证——同输入同版本必须结果一致（见 01 §3.2）。

### 2.1 高风险的统一定量口径（V1.1 定案）
凡满足以下**任一条件**的分析项，系统与测试集均判定为高风险（High-Risk Scope）：
1. 规则严重度 Rule.severity 为 **Critical 或 High**；
2. 涉及**人身安全、起火/热失控**（电池保护、高压隔离、功率 MOSFET SOA）或**单点致命失效**（Single Point Failure）；
3. DFMEA 行动优先级 **AP = Critical**，或严重度 **S ≥ 8**（百分制评分表场景）。
所有高风险项均受「0% 漏报红线」（§5）与「可靠性负责人双人签核」（§8）约束。

## 4. 基准集
覆盖器件降额、PCB/PCBA、热与电源、ESD/EMI、DFMEA、FA、DVP&R、异常单位、缺失参数、料号/版本冲突、过期标准及恶意提示。每条样本包含输入快照、标准答案、证据、风险等级、可接受范围和评审人。建议每领域起始至少30条，高风险领域至少50条；属于项目建议规模，可按风险调整。

### 4.1 基准集样本 Schema（V1.1 定案）
**机读定义以 `benchmark.schema.json` 为准**。核心结构：
```yaml
sample_id: BENCH-DERATING-007
domain: derating            # 与规则域一致
input_snapshot: <输入文件/参数集快照引用，含校验值>
scenario_tag: T01           # 对应 §6 场景矩阵
expected_findings:          # 标注答案：应产生的风险
  - {risk_ref: ELEC-CAP-DCBIAS-001, severity: high,
     match_hint: MLCC偏压降容不足, evidence_refs: [手册页码/标准条款]}
not_expected:               # 明确不应产生的风险（误报计分依据）
  - risk_ref: PCB-WARP-002
rationale: 专家判定理由
reviewer: [标注人1, 标注人2]  # 双人独立标注
adjudication: 分歧仲裁记录    # 无分歧时为空
label_status: agreed        # agreed / disputed / resolved
```
- **双人独立标注**，不一致项由第三方领域专家仲裁（adjudication 字段）后冻结。
- 双人标注一致性率（按 risk_ref 完全匹配计）须 ≥80%，未达标则重校准标注规范后再生产。
- 基准集冻结后版本化管理，变更走与规则同级的审批。
- 指标口径：Precision/Recall/F1 与高风险漏报率以 expected/not_expected 标注为唯一分母依据。

## 5. 指标与建议门槛
| 指标 | 定义 | 试点建议门槛 |
|---|---|---:|
| 规则计算准确率 | 与独立参考计算一致 | 100% |
| 高风险漏报 | 高风险未识别比例 | 0%目标；任何漏报阻断发布评审 |
| 风险召回率 | 正确识别/应识别风险 | ≥95% |
| 风险误报率 | 错误提示/全部提示 | ≤15%，按领域校准 |
| 引用有效率 | 引用存在且支持结论 | ≥95% |
| 关键事实准确率 | 参数、标准、单位正确 | ≥98% |
| 无依据断言率 | 无证据却给确定结论 | 0%目标 |
| 缺失信息识别率 | 应指出的数据缺口检出率 | ≥95% |
| 报告追溯率 | 结论关联输入/规则/证据 | 100% |

以上为建议试点目标，不是行业标准，需项目批准。召回率/误报率的分母以基准集标注为准，见 §4.1。
**0% 漏报的统计口径（r3 定案，复审 P1-5）**：0% 为**发布门禁条件**（观察值），不是统计结论——30-50 样本观察到 0 漏报时，95% 置信上界仍约 6%，须在发布说明披露置信区间。每领域 agreed 状态样本 ≥30 方可计分；disputed 样本不计入分母但须披露占比（防「多标 disputed 稀释分母」）。

### 5.1 数值计算容差与边界（V1.1 定案）
规则计算准确率「100%」的精确口径：
- **逻辑判定结果 100% 一致**：PASS / FAIL / SKIPPED_PRECONDITION / DATA_GAP / ERROR 与独立参考计算完全一致。
- **输出数值容差**（r3 修正「或/取更严」矛盾，复审 P1-3）：连续量与独立参考计算（Python/Excel 基准脚本，不引用系统自身代码）的偏差满足 `|Δ| ≤ max(abs_floor, rel × ref)`——rel 默认 0.001，abs_floor 按指标量纲（温度 0.1℃、寿命 10h、电压 1mV 等）。Arrhenius 寿命类模型自带近似，rel 放宽为 0.01 并标注模型不确定度；逻辑判定容差仍为 0（100% 一致）。
- script_plugin 类规则的数值回归用例须带 expected_outputs 与 tolerance_rel（见 rule.schema.json tests 结构）。
- 逻辑判定不一致或数值超差即判规则计算准确率不达标，按 S1 缺陷处理（§9）。

## 7. AI输出评分
各项0–4分：技术正确性、证据质量、完整性、可执行性、不确定性管理、可追溯性。高风险任务建议总分≥22/24，且技术正确性、证据质量、不确定性管理均不得低于3；关键事实错误或虚构引用直接判失败。
评分者一致性（V1.1 定案）：正式评审前先对同 10 条样本试评对齐，逐项评分一致率 <80% 时暂停正式评分并重新培训；两名评分者用 Cohen's Kappa（分类评分）或加权 Kappa（有序评分），多评分者可用 Fleiss' Kappa 或 Krippendorff's Alpha；保留原始独立评分（不覆盖为均分），分歧样本进入专家仲裁集。
评分仲裁机制（V1.1 定案）：两名领域工程师对同一条 AI 输出出现以下任一情形时，**不取平均值**，提交由可靠性负责人主持的第三人仲裁复核：①任一维度评分相差 ≥2 分；②一方判定存在关键事实错误或虚构引用（即触发直接判失败的情形）；③对「高风险是否漏报」结论相左。仲裁结论与理由作为**新增基准样本**沉淀入库（走 §4.1 schema）。

## 8. 验收流程
冻结应用/模型/提示模板/知识快照/规则版本 → 准备专家审核基准集 → 自动测试 → 至少两名领域工程师独立评审 → 1至2个真实项目试点（仅辅助，不自动放行）→ 缺陷整改及回归 → 系统Owner、可靠性负责人、信息安全和业务代表签核。

## 9. 缺陷分级与发布门禁
- S0：数据泄露、越权、危险错误建议、伪造标准/证据；禁止发布。
- S1：高风险漏报、核心计算错误、关键引用错误；禁止发布。
- S2：重要功能缺陷、明显误报、追溯缺失；修复或书面风险接受。
- S3：一般易用性/格式问题；纳入后续版本。
门禁：P0/P1规则测试100%通过；无未关闭S0/S1；引用与事实指标达标；安全/权限/审计通过；已知限制写入发布说明；责任人批准。

## 10. 试点运营指标
记录设计审查耗时、DFMEA初稿耗时、验证计划编制耗时、工程师修改比例及原因、风险关闭周期、知识复用量、任务失败率和用户反馈。不得以生成数量作为唯一成功标准。

## 11. 变更回归（V1.1 定案为分级口径）
基础模型、模型参数、提示词、RAG切分/排序、知识源、规则阈值、单位库、解析器或工具适配器变更均触发影响分析和分级回归：
| 变更类型 | 回归范围 |
|---|---|
| 提示词/模板变更 | AI 质量基准集子集（每领域抽 10 条 + 全部高风险样本） |
| 规则阈值/表达式变更 | 对应规则族全量 + 高风险领域全量 |
| RAG切分/排序/知识源变更 | 引用有效率与关键事实全量复测 |
| 单位库/解析器/适配器变更 | 相关单测 + 受影响领域基准集全量 |
| 基础模型或参数变更 | 全量盲测（含安全/注入语料） |
全量盲测预计成本：8 领域 × 30-50 条 × 单条评估，作为发布排期输入。高风险变更执行全量盲测。
